使用教程 · v1.0.9

DPCL · Plain Craft Launcher

基于 PCL 开源版二次开发的 Minecraft 启动器。这份教程按「打开它、用熟它」的顺序组织， 每一节都可以单独阅读，也可以从头到尾走一遍。

Minecraft 启动器 PCL 开源版衍生 离线可用 内置汉化工作台
01

写在前面

DPCL 是基于 PCL 2 在下载风波后开源的 2.99 版本二次开发而来。主体完全由 AI 开发， 不保证代码质量，但已尽量不过度修改 PCL 原本的交互逻辑，以维持稳定。

它并不是一个正式发布的商业产品，更接近「开源的学习作品 + 服务器上勉强够用的工具」。 这决定了它的性格：功能很多，细节偶尔毛糙，但真的能帮你把 Minecraft 玩得更顺手一点。

关于名字

PCL 使用自定义开源协议，要求保留赞助渠道与 PCL 名称。DPCL 在第一个正式版时已经确定了名字， 因此没有加前缀，但保留了更多的赞助与开发者信息。如果确有版权需要，欢迎通过 issue 或其它方式通知我们。

DST 是什么

DST 是围绕 DST Bot V2 的软件生态。DPCL 最早是在 PCL 出事时为公益服开发的定制启动器，用于查看服务器列表并保证能正常下载，后来在不断的小想法里完善成了正式启动器。

02

开始使用前

第一步：ClientID 与 CurseForge Key

DPCL 的发布版不内置 ClientID 与 CurseForge Key。ClientID 是微软应用 ID，决定能否登录正版账号； CurseForge Key 用于搜索模组。想完全脱离云端使用，需要自行在设置里填写这两项。

设置 → 其他：下载源、网络协议，以及「账号与 API」里的微软 ClientID 与 CurseForge Key。

普通用户不需要手动填写。只要在下面的位置选择一次机器人预设群，就会自动同步 ClientID 与 CurseForge Key 到本地。

设置 → 机器人：选择一个群作为启动器使用的群，即可同步预设。

也欢迎加入我们的服务器。如果哪天服务器没了，可以去找 trop。

03

离线功能拓展

DPCL 为版本设置补上了存档、资源包、光影包、截图管理与收藏夹。这不是简单的文件列表，其中大部分都具备不俗的编辑能力。

版本设置 → 存档管理：支持全部 / 有图标 / 无图标筛选，右键存档即可进入编辑页。

存档管理03a

存档管理是 DPCL 最强大的功能之一。它提供直接读取存档数据的能力，能帮玩家解决一些致命 BUG，也方便地图开发者做高级开发。

当前提供五项能力：世界设置、数据包、区域文件、玩家数据、地图管理。

世界设置：读取并编辑 level.dat，常见键都提供了便捷的编辑方式。

数据包：类似模组管理的管理页（制作较早，未完全遵循 PCL 设计，但可正常使用）。

玩家数据：可编辑玩家 NBT，提供物品栏、末影箱的易用编辑，也可直接编辑原始 NBT。整合包有大量自定义 NBT 时尤其实用。

通过对玩家数据的编辑，可以解决生命值 NaN 之类的问题。区域文件功能目前能力较弱，未来计划加入直接的方块编辑。

地图预览03b

这是 DPCL 较重磅的功能：直接读取地图文件，在游戏外渲染世界地图。适合分享或记录自己的世界，而且不受游戏内地图的预览范围限制。

渲染设置：选择维度与范围，读取区块数据后画出俯视图。

渲染结果：鼠标悬停可查看坐标与方块信息。

坦率地说

虽然不想承认，但这更像是一个「不实用的有趣功能」：较大范围渲染会极度耗时。已知 BUG 仍有两处：水体渲染异常，以及右键补渲染异常（错误地使用了旧渲染引擎，在没有高度数据时无法正确补充渲染）。

04

收藏夹

方便玩家快速安装喜爱的辅助模组，也方便整合包作者快速安装必备模组。不局限于模组，大部分资源都能被收藏，还能与朋友分享。

收藏夹：包含收藏资源信息，支持分享收藏、导入分享码、全选与安装到版本。在资源管理页里，小五角星就是收藏按钮。

选择想要的模组即可快速安装到当前版本，会自动挑选合适的版本；安装功能会智能解析去重并获取前置，所以会有一些时间损耗，但值得。

分享不是上传

分享会把收藏数据编码成分享码，而不是上传数据。分享码 + 微信也是不错的同步方案。

云同步

支持云同步，但依赖 dstbot 的云服务，并需要绑定 QQ 账号后才能使用。

05

联机

DPCL 把 PCL 开源版中隐藏的联机能力重新启用并加以优化。技术上沿用 easytier 组网方案；由于无法维护联机服务器，只内置两个公益节点（需要通过 GitHub 仓库同步预设）。

必须关闭防火墙

否则会出现连接错误。

联机页：可以创建或加入房间。

节点：从预设节点中选择延迟较低的，也可以填写自己知道的节点 IP。

传统 PCL 方案会维护节点列表，让加入者知道正确的 IP。DPCL 则把节点 IP 直接编码进邀请码里，于是邀请码更长、也存在一定风险，但使用起来更轻松。加入未知节点的房间时，DPCL 会提醒安全风险；easytier 的加密连接可以尽量保证信息安全。

06

百宝箱

PCL 开源版并不包含百宝箱，所以我们重新制作了一些有趣的功能放在这里。

音乐播放器

内置音乐播放，取代个性化里的简单音乐能力。可在设置中登录网易云音乐获取在线音乐，暂不支持歌词。

下载器

调用 PCL 的多线程下载工具，与 PCL 百宝箱中的那个是一样的东西。

内存优化

与 PCL 同理，把内存压入虚拟内存（硬盘）。效果不如 PCL，可能是 PCL 采用了更激进的数值。

音乐播放器：登录网易云音乐后可同步歌单，也能搜索歌曲与歌单。

07

汉化工具

汉化工具并不属于 DPCL，而是另一个开源项目 DST i18n platform。DPCL 提供了一键安装与启动的能力，在版本设置里可以快速开启此版本的汉化工作台。

版本设置 → 快捷方式：点击「创建汉化」即可进入汉化工作台。

它能为整合包快速制作本地化（LLM 或机器翻译）。第一次使用需要先下载那个副程序。

1

选择整合包目录

软件会自动解析工作目录，并扫描需要汉化的模组、KubeJS 与 FTB Quests。

2

设置 LLM 地址

在设置中编辑好 LLM 地址后，就可以让 LLM 自动汉化了。

3

审校并导出

LLM 会询问一些模组中的专业名词，让汉化更精良（该功能可以关闭）。完成后导出 zh_cn.json，或直接生成资源包。

左：自动找到需要汉化的模组、KubeJS、FTB Quests，并标注是否缺少 zh_cn。右：LLM 翻译后可逐条审校。

提示词中已经提醒 LLM 避开非本地化键值对的编辑。

08

界面与主题

DPCL 改善了 PCL 的主题界面，提供两套 UI 方案：PCL（classic） 与 PCL Indra。第一次打开时可以选择一套默认布局。

  • PCL 经典版开放了所有主题；「自定义主题」有一些问题，暂时不准备修复。
  • 定制主题允许用户完全设置各个主题色。
  • 除默认主题外，还有「高对比度」（黄/黑，强制深色）与深色模式。

左：经典浅色。右：深色模式。作者个人最喜欢经典浅色 + 玄素黑，深色下的橡木棕也不错。

PCL Indra：另一套完整的界面布局。

个性化包可以快捷导入导出，把背景图、自带音乐、主页文件与主题设置打包成一个 .dclart 文件，换机或分享给别人时一键还原。这个功能有不少 BUG，只能说「能用」。

09

在线功能

联网后，DPCL 可以展示 DST 生态服务器的服务器列表与公告，并同步群消息（需要绑定 QQ）。其中最重要的是 DST-Mode 登入能力。

启动页：左侧账号区，右侧服务器状态与群公告。

绑定 QQ09a

1

输入要绑定的 QQ 号

在机器人面板点击「绑定 QQ」，填入你的 QQ 号。

2

在群里回复 OK

发起后机器人会在群里 @你 并发送确认消息，5 分钟内回复 OK 即完成绑定。

3

开始使用在线能力

完成绑定后，消息查看、收藏夹同步等在线功能即可使用。

绑定对话框：输入要绑定的 QQ 号。

DST 登入09b

此部分推荐服主查看。登入能力由 DST-Mode 提供，类似皮肤站，同时兼容正版登入。服务器启动时携带 -javaagent 参数，并在指定目录安装好代理模组，即可接受正版与 QQ 登入的玩家。

1

登录 QQ

在启动页的 QQ 账号区点击「登录」，会提示输入游戏内使用的名字（3–16 位，只能包含字母、数字、下划线）。

2

检查正版重名

登入时会检查是否与正版用户同名（由 DST Bot 负责检测）。

3

启动游戏

启动器会自动携带 JVM 参数。使用 QQ 登入的玩家可以进入使用 DST-Mode 的服务器，正版玩家也能正常加入。

左：QQ 登录时设置游戏内名称。右：登录后可在 QQ 里发 /dst skin 绑定皮肤。

皮肤显示说明

正版玩家无法看到 QQ 玩家的皮肤（即使安装模组）；QQ 玩家可以看到正版玩家的皮肤。

10

结语与其他

自定义服务器

添加自定义服务器，查看它们的连接信息。

检查更新

点一下版本号即可检查更新（From Trop）。

群消息图片设为背景

快捷保存 QQ 消息中的图片作为启动器背景。

启动选项

启动游戏时可自动安装汉化材质包与通用拼音搜索。

协议设置

修改默认网络协议，解决部分资源下载过慢。

下载配置

下载源、版本列表源、线程数、速度限制、目标文件夹等都在设置中。

在 DPCL 的制作中，我们无数次遇到智能体自行从头设计已有功能。例如存档管理中的数据包管理。无论模型好坏，智能体在许愿式编程中的工程管理能力非常堪忧。其目的在于完成而不是如何完成。但这一问题可以通过预设的提示词规范好。

这是个人在此次开发中总结的部分经验，这在之前已经被提出过多次。也感谢以前的开发者提前踩雷，确保了软件在前期就没有造成过度修改。

Agent Prompt · 经验总结
1. 遇到常规做法报错时，禁止从头编写相关能力或用字节码、汇编等方式手动调整二进制文件，应先与使用者报告
2. 制作用于下载、配置等常用功能时，应解耦为独立模块，便于后续复用
3. 编写任意功能前，先回顾是否已有类似功能；如有，解耦并记录在 function.md 中
4. 注释应简洁干练地说明功能实现，而不是记录开发想法与用户要求
5. 上传时不应上传 agent 相关文件、测试工具等无关文件
6. 非必要不进行全量测试
